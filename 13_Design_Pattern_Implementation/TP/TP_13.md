### 1. Potongan Kode (*Code Snippet*)

Implementasi pola ini dapat ditemukan pada berkas `backend/src/services/todo.service.js`.

Proses isolasi dan pemetaan data dari baris mentah basis data ke objek aplikasi didefinisikan menggunakan fungsi penunjang khusus berikut:

```javascript
// Lokasi: backend/src/services/todo.service.js

const toTodoResponse = createRowMapper({
  id: (row) => String(row.id),
  userId: (row) => (row.user_id ? String(row.user_id) : null),
  ownerName: (row) => row.owner_name || null,
  title: "title",
  description: "description",
  completed: "completed",
  status: "status",
  statusName: (row) => row.status_name || row.status,
  priority: "priority",
  category: (row) => row.category_code || row.category,
  categoryName: (row) => row.category_name || row.category,
  dueDate: (row) => formatDate(row.due_date),
  dueTime: (row) => (row.due_time ? row.due_time.slice(0, 5) : ""),
  createdAt: "created_at",
  updatedAt: "updated_at",
});
```

Fungsi `toTodoResponse` di atas kemudian dipanggil secara konsisten di setiap fungsi pengambilan data (seperti `getTodos` atau `getTodoById`) untuk memastikan struktur data yang dikirimkan ke pelanggan (*frontend*) memiliki format yang seragam.

### 2. Penjelasan Desain (*Design Explanation*)

#### Nama Design Pattern

**Data Mapper Pattern** (*Pola Pemetaan Data*).

#### Tujuan Utama

Memisahkan representasi struktur data di dalam basis data (tabel relasional) dari representasi data di dalam memori aplikasi atau objek domain bisnis. Pola ini menjaga agar objek di sisi aplikasi tidak perlu mengetahui detail struktur tabel atau penamaan kolom spesifik yang ada pada database.

#### Cara Kerja pada Kode

1. **Perbedaan Konvensi Penamaan**  
   Basis data PostgreSQL pada proyek ini menggunakan konvensi penamaan **snake_case**, seperti `user_id`, `due_date`, dan `created_at`. Sementara itu, aplikasi Node.js/JavaScript dan frontend menggunakan format **camelCase**, seperti `userId`, `dueDate`, dan `createdAt`.

2. **Lapisan Pemeta (*Mapper Layer*)**  
   Fungsi `toTodoResponse` bertindak sebagai **Mapper**. Fungsi ini menerima baris mentah hasil kueri SQL (`row`), mengekstrak nilainya, melakukan transformasi data, lalu memetakannya ke dalam objek JavaScript baru yang siap digunakan oleh aplikasi.

3. **Transformasi Data**  
   Mapper juga menangani berbagai proses konversi data, seperti:
   - Mengubah nilai ID menjadi tipe `String`.
   - Mengonversi format tanggal menggunakan fungsi `formatDate()`.
   - Memotong format waktu menggunakan `.slice(0, 5)`.
   - Menangani nilai `null` agar tetap konsisten saat dikirim ke frontend.

## Keuntungan Menerapkan Pattern Ini

### 1. Loose Coupling (Keterikatan yang Lemah)

Apabila di kemudian hari terjadi perubahan nama kolom pada tabel basis data, misalnya `due_date` diubah menjadi `deadline`, maka perubahan hanya perlu dilakukan pada fungsi mapper. Kode pada lapisan controller maupun frontend tidak perlu diubah.

### 2. Encapsulation & Data Cleansing

Seluruh logika transformasi dan pembersihan data dipusatkan pada satu tempat. Hal ini mencegah logika konversi data tersebar di berbagai bagian aplikasi sehingga kode menjadi lebih rapi dan mudah dipelihara.

### 3. Single Responsibility Principle (SRP)

Sesuai prinsip **Single Responsibility Principle**, setiap komponen memiliki satu tanggung jawab utama:

- Service bertanggung jawab untuk mengambil dan memproses data.
- Mapper bertanggung jawab untuk mengubah format data dari database menjadi objek yang siap digunakan aplikasi.

Dengan pemisahan tanggung jawab ini, kode menjadi lebih terstruktur, mudah diuji (*testable*), dan lebih mudah dikembangkan di masa mendatang.
